# 运营部 · 任务与进展

用于业务、团队和库存管理的部门事项看板。成员记录任务及协作交付，老板查看部门全貌。

已部署在 [okr.zungyunai.top](https://okr.zungyunai.top)。线上使用腾讯云 Ubuntu 22.04、Node.js 20、systemd 和 nginx HTTPS 反向代理，Next.js 监听 `127.0.0.1:3001`。

## 启动与升级

运行环境需要 Node.js 20.9 或更高版本，以及 `python3`（数据库在线备份和测试使用，不依赖 sqlite3 命令行工具）。全新安装：

```bash
npm ci
cp .env.example .env  # 已有配置请保留，不要覆盖
npx prisma migrate deploy
npx prisma generate
npm run dev
```

浏览器打开 [http://localhost:3000](http://localhost:3000)。保留原来的 `AUTH_SECRET` 和 `DATABASE_URL`；新安装时将 `AUTH_SECRET` 改为随机字符串。

已有数据升级使用 `prisma migrate deploy`，不要使用数据库重置命令。迁移保留任务 ID、原负责人、原所属周、状态和目标关联；旧任务的完成时间沿用原记录更新时间，并在历史记录中说明。不会给旧任务自动生成虚假的进度确认。

SQLite 默认位于 `prisma/dev.db`。升级前应使用 SQLite backup 方式备份，运行期间不要仅复制主文件而遗漏 WAL。代码提交到 Git 不会同步数据库。

**每次上线前必须先执行 `scripts/backup-db.sh`，确认成功后再升级和迁移：**

```bash
./scripts/backup-db.sh
npm ci
npx prisma migrate deploy
npx prisma generate
npm run build
# 按服务器现有流程重启 systemd 服务
```

脚本读取项目根目录 `.env` 的 `DATABASE_URL`；`file:./dev.db` 相对 `prisma/`，也支持绝对路径。备份默认保存为 `~/okr-backups/okr-YYYYMMDD-HHMMSS.db`，完成后执行 `PRAGMA integrity_check`，失败会以非零状态退出，且不清理旧备份；成功后只保留最近 30 份。同一秒重复执行会报错，避免覆盖已有备份。可用 `BACKUP_DIR=/其他目录 ./scripts/backup-db.sh` 覆盖输出目录。全新空库请先完成安装，之后每次上线均需备份。

Prisma 6 的 seed 配置位于 `prisma.config.ts`，显式加载根目录 `.env`，外部设置的 `DATABASE_URL` 优先。保留 Prisma 6，不执行数据库重置。

生产环境的会话 Cookie 仅通过 HTTPS 发送。登录按规范化账号 + 客户端 IP 计数（优先取 nginx 设置的 `X-Real-IP`，否则取 `X-Forwarded-For` 最后一个值），十分钟内失败五次锁定十分钟，成功清零；该限制仅保存在单进程内存中，重启清零，不支持多进程共享。nginx 须设置 `proxy_set_header X-Real-IP $remote_addr;`（线上已配置）。

## 周期、协作与汇报

数据模型见上一版：Period（周 / 月 / 季）、WorkPackage / Deliverable、RACI（与账号角色分开）、Check-in（尚未提交本周进展）。本版在此之上提供周期汇报页面与老板下钻，不改表结构，也不做数据库重置。

- **Period**：周 / 月 / 季树（Week→Month→Quarter）。季度标签与原 `cycle` 字符串一致（如 `2026-Q3`），月份为 `2026-09`，周为 ISO 周标签（如 `2026-W37`），日历与 `lib/week.ts` 对齐，业务时区仍为 Asia/Shanghai。
- **Check-in**：周更新按任务、月复盘按关键结果、季评估按目标。主负责人更新任务进展会在同一事务自动记录本周汇报。`SUBMITTED` 为提交进展事实，`NO_CHANGE` 为确认暂无变化。任务进展审计仍用 `TaskUpdate`。
- 例行任务可以不挂 `keyResultId`：计入任务完成率，不计入 KR 达成率。

`TaskCollaborator` / `TaskMilestone` 保留；协作者交付文案会复制一份到 `Deliverable`，原协作行不删除。完整协作子项编辑、成员邀请和通知仍不在本版。

## 周期汇报与老板下钻

- **周期总览** [`/overview`](/overview)：周更新 / 月复盘 / 季评估，用 `ensurePeriodTree` 保证当前周、月、季存在。地址参数 `kind`、`period`、`exception`、`person` 可原样带回。
- **Check-in**：范围为任务 / 关键结果 / 目标。没有记录就是「本周还没写进展」，不会自动生成空记录。「确认暂无变化」(`NO_CHANGE`) 与未汇报不是一回事。
- **管理层**：可为主责汇报人或督办确认人的范围提交汇报。老板只读，填报成员可写。
- **老板**：同一总览只读。异常筛选（风险 / 逾期 / 本周还没写进展 / 待确认）进入筛选后的 [`/tasks`](/tasks)，再进入任务详情查看协作、交付物和 Check-in 历史；返回时保留周期与筛选。
- **目标下钻** [`/okrs/[id]`](/okrs)：关联任务、交付物、KR / 目标汇报。任务完成率与 KR 达成率分开显示。

周期任务范围包含：在周期结束前创建、且尚未结束或结束时间不早于周期开始的未归档任务；再与原有排期、期限和月 / 季目标关联条件取并集。周期开始前已取消的任务排除。本周完成仍计入完成率，取消任务不计入完成率，也不要求周汇报。

创建任务同步主负责人的 R/A；移交同步删除旧负责人 R/A、写入新负责人 R/A；协作添加 / 移除同步 C。以上与任务及历史记录在同一事务中提交。C 只能记录个人交付，不能代交 Check-in。

### 已有数据回填

本次不改表结构。升级前先备份并暂停旧版本的业务写入，使用新代码运行：

```bash
npm run db:backfill -- --dry-run
npm run db:backfill
npm run db:backfill  # 同一批数据再次执行应 total=0
```

命令用 `dotenv/config` 读取项目根目录 `.env`，外部 `DATABASE_URL` 优先，与 `prisma.config.ts` 一致。预览只读，打印按类别划分的变更数量；正式执行在单个事务中建立周期树、补目标 `periodId`、以当前任务负责人修正 R/A、补活跃协作者 C、复制协作交付物。保留原任务、进展、Check-in、协作行和已有交付物；不会补造汇报、期限或任务排期。已有目标的无效 `cycle` 沿用基础回填行为，关联到当前季度，`cycle` 原文保留。

可运行 `npx tsx scripts/rehearse-backfill.ts` 复现 15 条无排期任务的临时数据库演练，脚本不会使用当前配置的数据库。完整验收与上线顺序见 [本次交付记录](docs/checkin-integrity-validation.md)。

目标 / KR 的写入在服务层校验负责人、文本长度、周期格式、指标方向及有限数值；有任务或对应范围 Check-in 的目标 / KR 不允许删除，包含目标下 KR 的关联。失败通过 `/okrs?error=...` 显示中文原因，老板写入继续由服务端禁止。

## 第一版工作流程

1. 新建事项只需 3 个问题：这件事是什么、做到什么算完成、谁负责（默认自己）。跟进日默认 3 天后，可选明天、下周一或自选日期；更多设置默认折叠，期限、领域、目标、重要程度、范围和下一步均选填。下一步留空默认为「明确推进计划」。有完成期限自动作为短期任务，无期限作为长期事项。
2. 安排协作：主负责人指定协作者、交付内容和期限。协作者只能更新自己的交付。
3. 更新进展先选「现在怎么样」：顺利推进、有风险、在等别人、卡住了、做完了或没变化。风险和卡住需写原因与支持，做完了写最后结果；不做了从次要入口取消并说明原因。下一步自动带出原值，跟进日支持快捷选择。没变化保留已有事实，只确认并调整跟进日。主负责人本周更新进展即视为已汇报（包括没变化、完成、取消），无需再写周汇报；月复盘与季评估仍在原入口提交。旧的独立汇报入口与历史记录继续有效。
4. 长期事项按关键节点推进，节点或个人交付完成都不会自动把整体任务标为完成。
5. 完成或取消后可以归档，也可以恢复或重新开启，历史记录持续保留。

首页及任务清单按所有未结束事项查询，不按自然周隔断任务；周期汇报页按周 / 月 / 季查看。旧 `/week` 链接会转到任务清单。周完成数仅统计完成时间位于本周的任务。日期以 Asia/Shanghai 为业务时区。

风险、整体逾期和跟进确认到期分别显示。刚创建或移交的任务显示「刚创建 / 刚接手，待更新进展」，不会自动宣称按计划。

## 权限与保存

- 老板账号：读取总览、任务详情及目标，所有业务写入在服务端禁止。
- 填报成员：可创建任务、维护资料和调整分工；主负责人更新整体进展、安排协作和关键节点；协作者更新自己的交付。
- 移交会清除当前确认标记，由新负责人重新确认。原老板名下的历史任务保留，由填报成员移交接手。
- 每次更新与历史记录在同一事务保存。表单携带版本号，旧页面提交会提示刷新，不会覆盖别人刚保存的修改。
- 任务采用归档保留机制；原有目标编辑功能仍保留。

目标支持「提升」和「降低」两种方向及起点值。例如 ACOS 起点 35、目标 25、当前 30 的进度为 50%。不能将不同指标的百分比简单当作部门总体表现。

本版包含页面内到期跟进提示；定时外部通知、周期任务自动生成和独立复盘快照安排在后续版本。多人异地使用请访问已部署的同一服务，并做好数据库备份。

## 成员管理与修改密码

- 老板导航中的「成员」进入 `/members`，可新增账号、修改姓名与角色、设置临时密码、停用或启用账号。成员无法访问此页面；老板对任务、目标、进展等业务数据仍然只读。
- 登录账号与登录页使用同一规范化：全角转半角、移除零宽字符及空白、转小写，短账号自动补 `@okr.local`。重复账号提示「账号已存在」。姓名为 1–40 字。
- 初始密码、重置密码、新密码均先按原登录规则规范化（NFKC、去零宽字符、去首尾空白，保留中间空格），再校验 8–72 字符并以 bcrypt cost 10 保存。
- 新建账号和被重置密码的账号登录后必须先到 `/account` 设置新密码；所有业务页面与写入入口均由服务端拦截。所有人可在退出登录附近点击「修改密码」，输入当前密码完成修改。
- 停用后无法登录，已有会话立即失效；再次启用也不会恢复旧 Cookie，原密码仍可用于重新登录。历史任务、协作、进展、汇报及筛选中的姓名均保留，不删除账号或业务记录。停用前必须先移交该成员主责的全部未结束任务；完成和取消的任务不阻止停用。
- 停用成员不再出现在任务主负责人和协作者选择框中，服务端也拒绝指定停用账号。不能停用自己或把自己从老板改为填报成员；管理事务始终保留至少一位未停用老板。
- 重置密码会使该成员所有设备的会话失效；本人改密重新签发当前设备 Cookie，其余设备须重新登录。会话每次查库读取当前角色与停用状态，签发时间以秒为单位保留毫秒精度，并校验密码修订时间，覆盖同一秒内的连续操作。

**上线需要执行 `prisma migrate deploy`（本次有新迁移 `20261016120000_member_admin`）。** 迁移只为 User 增加 `disabledAt`、`passwordChangedAt`、`mustChangePassword`，现有账号默认保持可登录且无需改密，不修改原密码。沿用上文的备份、安装、迁移、生成 Prisma Client、构建和重启顺序，切勿重置数据库。
