# 页面重做设计规范（v1）

负责人已选定：**B 卡片式布局 + C 的“一句话结论” + 新填写方式（一点就选）**。
可交互原型：`docs/design/prototype.html`（浏览器直接打开；顶部切到「B 卡片式」「新填写方式」，以及「手机」）。原型里的数据是演示数据，实现时一律用真实数据。

本规范是实现与验收的唯一依据。原型与本规范冲突时，以本规范为准。

## 0. 原则

1. **任务是主角。** 首页回答三件事：今天要跟进什么、谁在等我交付、哪些事还没定期限。目标 / KR、月度复盘、季度评估退到二级入口。
2. **先说结论。** 每个首页顶部有一句结论（见 §4.1），老板不用看完整页也知道情况。
3. **少填、给选项、给例子。** 选择题一律用“选项胶囊”（§3.3），不用下拉框；每个输入框有一句帮助文字和“例：…”。
4. **日常用语。** 页面上不出现 RACI、WBS、Check-in、KR 缩写解释、“无行”等术语；“关键结果”可保留在目标页面。
5. **手机能用。** 390px 宽度下无横向滚动；点击区域 ≥ 44×44px；手机端用底部导航。
6. **只换外观，不改规则。** 业务规则、URL、表单字段名、server action 一律不变；数据来自 `lib/*-view.ts`，需要的新计算加到 lib 并写单测。

### 字体
**不使用 Google Fonts**（国内访问不稳定），全部用系统字体：
- 正文：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`
- 标题（页面大标题、栏目标题、一句话结论、深色条里的数字）：`"Songti SC", "STSong", "Noto Serif SC", "Source Han Serif SC", serif`，字重 700
- 数字 / 日期：正文字体 + `font-variant-numeric: tabular-nums`

现有 `layout.tsx` 中通过 next/font 加载的 Geist / Newsreader 移除。

字号：正文 14px / 行高 1.6；卡片标题 15px 700；栏目标题 18px；页面大标题 30px（手机 24px）；一句话结论 26px（手机 22px）；辅助文字 12–13px。

### 形状与间距
- 圆角：卡片 14px；大面板 / 深色条 18px；输入框 12px；按钮、选项胶囊、徽章 999px（胶囊形）
- 间距刻度：4 / 8 / 12 / 16 / 20 / 24 / 32 / 48
- 阴影：卡片默认无阴影，悬停 `0 4px 14px rgba(30,27,22,.07)`
- 内容最大宽度 1280px，左右留白：桌面 32px、手机 16px

## 2. 布局与导航

### 桌面（≥ 720px）：顶栏
左：品牌（绿色方块“运” + “运营部看板”）。中：导航胶囊——**工作台 `/`、全部事项 `/tasks`、每周进展 `/overview`、目标 `/okrs`、成员 `/members`（仅老板）**。当前页为深色实心胶囊。右：姓名 · 角色，点开小菜单：修改密码 `/account`、填写指南 `/guide`、退出登录。

### 手机（< 720px）：顶部简化 + 底部导航
顶部只留品牌和页面标题。底部固定导航 5 项：**工作台 / 事项 / ＋（中间凸起的圆形主按钮，新建事项；老板账号不显示，改为 4 项）/ 每周进展 / 我的**（`/account`，页面内含修改密码、填写指南、成员管理（仅老板）、退出登录）。底部导航高 56px + 安全区 `env(safe-area-inset-bottom)`；页面底部留出相应空白。

老板账号：所有写操作入口隐藏，顶栏右侧显示“只看不改”。

## 3. 组件（放在 `components/ui/`，每个组件列出全部状态）

### 3.1 Button
- 类型：`primary`（绿底白字）、`secondary`（白底、`--line-strong` 边框）、`danger`（白底、risk 字色与边框，用于取消 / 停用 / 归档）、`text`（无底，绿色字）
- 尺寸：默认高 40px；`lg` 48px（表单主提交，手机端默认用 lg）；`sm` 34px（卡片内）
- 状态：默认 / 悬停 / 按下 / 聚焦（2px `--primary` 外描边，偏移 2px）/ 提交中（文字变为“保存中…”，禁止重复点击，沿用 `useFormStatus`）/ 禁用（40% 透明，不可点）

### 3.2 StatusBadge / Chip（只读）
胶囊形，高 24px，12px 字，按 §1 状态色。类型：任务状态、跟进（“跟进 今天”“晚了 2 天”“跟进 10/21”）、期限（“期限 10/24”“期限 未定”）、优先级（只有“重要”时才显示）、“已停用”、“只看不改”。

### 3.3 ChoiceChips（单选题，替代下拉框）
- 语义：`<fieldset>` + `<legend>` + 一组 `<input type="radio">`，每个选项是 `<label>` 包住 radio，radio 视觉隐藏但可聚焦；选择结果作为普通表单字段提交，不依赖客户端状态。
- 外观：高 40px（手机 44px）胶囊，白底灰边；选中为深色实心（`--ink` 底白字）；“卡住了 / 有风险 / 不做了”选中为 risk 实心；“做完了”选中为 primary 实心。
- 用于：现在怎么样（mood）、什么时候再看一眼（followPreset：明天 / 3 天后 / 下周一 / 选日期…；选“选日期…”时才显示日期框）、属于哪块（area）、重要程度（priority）、协作交付状态（推进中 / 已交付）、角色（填报成员 / 老板）。
- 选项变化时只显示需要的输入框（可用客户端组件控制显隐；被隐藏的字段不提交或由服务端忽略）。

### 3.4 Field
标签（15px 700）+ 同行灰色帮助文字（12px）+ 输入框（白底、`--line-strong` 边框、圆角 12、高 ≥ 44、聚焦 2px 绿色描边）+ 占位“例：…”。错误时边框 risk 色，下方 risk 字色提示。

### 3.5 TaskCard
白底卡片，内边距 16，整卡是一个链接（到任务详情，保留当前筛选参数）。从上到下：徽章行（状态、跟进）→ 标题（15px 700）→ 一行说明（按所在栏目不同：下一步 / 我要交 / 卡点 / 最新进展）→ 虚线分隔 → 底行（领域 · 主负责人；右侧“期限 …”）。
状态：默认 / 悬停（边框加深 + 阴影）/ 聚焦 / 受阻有风险（说明行显示卡点原文，徽章 risk）/ 已完成（标题 70% 透明 + ✓）/ 老板只读（无任何操作按钮）。
可选右下角次要操作（仅主负责人、仅“本周进展”相关位置）：“暂无变化”小按钮。

### 3.6 Lane（栏目）
标题（宋体 18px）+ 数量 + 一行灰色说明 + 卡片列表；空状态为虚线框“这里没有事项。”（工作台的“今天要跟进”为空时写“今天没有要跟进的事。”）。桌面三栏 `repeat(auto-fit, minmax(300px, 1fr))`；手机变为顶部胶囊切换（今天跟进 N / 等我交付 N / 没定期限 N），一次显示一栏。

### 3.7 WeekBand（本周进展深色条）
左：“本周进展” + 宋体大字“已写 X / Y” + “没变化点「暂无变化」也算写过”。右：未写的事项，每项一个深色内胶囊：事项名 + （成员）白色小按钮“暂无变化”/（老板）“某某 还没写”。全部写完时显示“这周都写完了”。“暂无变化”按钮提交现有的 progress same 操作（需要 taskId 与 version）。

### 3.8 Headline（一句话结论）
宋体 26px，最多两句，下面可有一行灰色补充。规则见 §4.1。

### 3.9 PersonCard（仅老板工作台）
头像圆（姓名最后一个字）+ 姓名 + “主责 N · 协作 M” + 右侧徽章：有受阻 / 有风险的主责事项 → risk“有事卡住”，否则 ok“正常”。点击进入 `/tasks?person=<id>`。

### 3.10 Timeline（动态）
每条：绿色小圆点 + “谁 做了什么” + 时间（12px 灰）。

### 3.11 Notice
成功（ok 色）/ 错误（risk 色）/ 提示（plain 色），圆角 12，可选关闭。

## 4. 页面

### 4.1 工作台 `/`
顶部：日期行（“10 月 16 日 周五 · 第 42 周”，上海时区）→ 一句话结论 → 补充一行 →（成员）主按钮“记一件事”。

**一句话结论规则**（在 lib 里实现为纯函数并写单测）：
- 成员：
  - 有今天要跟进的：“今天有 N 件事要跟进。”；若有等我交付：追加“X 在等你的「交付内容」。”（取最早期限的一条；多于一条时写“还有 M 项等你交付。”）
  - 没有今天要跟进、但有等我交付：“今天没有到期的跟进，X 在等你的「交付内容」。”
  - 都没有：“今天没有要跟进的事。”补充行：“可以推进还没定期限的事项。”
- 老板：
  - 有受阻 / 有风险：“N 件事在推进，M 件卡住了，需要你出面。”补充行：第一件受阻事项的“主负责人：卡点原文”（截断 60 字）。
  - 没有：“N 件事在推进，没有卡住的。”补充行：“今天该有回音的 K 件。”

**本周进展**：WeekBand。成员范围 = 自己主责的、本周应写的事项；老板范围 = 全部本周应写的事项（口径与 `/overview` 周视图一致，复用现有计算）。

**老板专属**：PersonCard 一排（所有未停用成员）。

**三栏**（同一任务只出现在第一个匹配的栏目里）：
- 成员：① 今天要跟进 = 我主责、未结束、跟进状态为今天 / 已过 / 未设置；说明行“下一步：…” ② 等我交付 = 我是协作者、交付未完成、任务未结束；说明行“我要交：…” ③ 我负责 · 还没定期限 = 我主责、未结束、无完成期限；说明行为最新进展
- 老板：① 需要你出面 = 未结束且受阻或有风险；说明行为卡点 ② 今天该有回音 = 跟进今天 / 已过 ③ 还没定期限 = 其余无完成期限的未结束事项

页面最下方：“最近动态”（最近 8 条，Timeline）。

### 4.2 新建事项 `/tasks/new`
标题“记一件事”，副标题“只要回答 3 个问题，30 秒记下来。其他的以后再补。”
1. 这件事是什么？2. 做到什么算完成？3. 谁负责？（成员 ChoiceChips，默认自己；成员多于 6 人时改为下拉框）→ 什么时候再看一眼？（ChoiceChips）→ “＋ 更多设置（选填）”展开：属于哪块（ChoiceChips）、最晚什么时候完成（日期，可空）、为哪个目标做的（下拉，可不选）、重要程度（ChoiceChips 一般 / 重要）、关联范围、下一步。提交按钮“记下来”（lg）；手机端提交按钮吸底。

### 4.3 任务详情 `/tasks/[id]`
- 返回链接（保留来源筛选）
- 头部：徽章行（状态、跟进、期限、重要）→ 标题（宋体 26px）→ “领域 · 主负责人 · 范围”
- 若有风险 / 受阻：risk 色提示块“需要支持：…”
- **主负责人**：首要卡片“更新进展”——现在怎么样（ChoiceChips：顺利推进 / 有风险 / 在等别人 / 卡住了 / 做完了 / 没变化），按选择显示需要的框；底部文字按钮“不做了（取消）”；说明“这次更新会自动算作本周进展”。
- **协作者**：首要卡片“我的交付”——交付内容、期限、交付状态（ChoiceChips）、我的进展、保存。
- 信息卡：做到什么算完成 / 最新进展 / 下一步 · 跟进日 / 完成期限 / 关联目标 / 本周进展状态
- 协作分工（卡片列表；主负责人可“＋ 安排协作”“移除”）
- 关键节点（勾选列表；主负责人可新增）
- 动态（Timeline）
- 折叠区“任务资料与分工”：编辑资料、移交负责人（移交前确认文案：“确定移交给【某某】吗？移交后你将不再负责更新进展。”）、完成或取消后的归档 / 恢复
- 老板：所有表单不渲染，头部显示“只看不改”。

### 4.4 全部事项 `/tasks`
标题“全部事项”。筛选条：搜索框 + 成员（下拉）+ 领域（ChoiceChips 风格的链接胶囊）+ 查看范围胶囊（未结束 / 需关注 / 待跟进 / 本周完成 / 已结束 / 已归档）+（成员）与我相关（全部 / 我主责的 / 我协作的）。激活的筛选显示为深色胶囊并带数量，右侧“清除筛选”。下方 TaskCard 网格。周期下钻参数（kind / period / exception）继续支持，此时顶部显示“周期下钻：第 42 周 · 本周还没写进展”和返回链接。

### 4.5 每周进展 `/overview`
标题“每周进展”。顶部周期切换（周 / 月 / 季三个胶囊 + 上一期 / 下一期）。周视图：WeekBand（全员范围）+ 按成员分组的“还没写”列表（每组可折叠，成员本人可一键“暂无变化”）+ 异常胶囊（风险 / 逾期 / 本周还没写进展 / 待更新）链接到筛选后的全部事项。月 / 季视图：沿用现有内容，换成新组件外观，并在顶部说明“月度看关键结果、季度看目标”。

### 4.6 目标 `/okrs`、`/okrs/[id]`
卡片化：目标卡片（标题、负责人、季度、业务指标达成度进度条、关键结果列表、关联事项数）。详情页重点列出“为这个目标在推进的事项”（TaskCard）与关键结果。编辑表单沿用现有字段，换成新组件外观。

### 4.7 成员 `/members`、账号 `/account`、登录 `/login`、指南 `/guide`
- 成员：成员卡片列表（姓名、账号、角色徽章、状态、主责未结束数）+ 右上“＋ 新增成员”（展开表单）；每张卡片的操作收在“…”菜单或折叠区：改名 / 改角色、重置密码、停用 / 启用。
- 账号：手机端即“我的”页：姓名、账号、角色；修改密码；（老板）成员管理入口；填写指南；退出登录。
- 登录：居中卡片，品牌 + 账号 + 密码 + “进入看板”，`--bg` 底。
- 指南：三段——记一件事（3 个问题）/ 更新进展（现在怎么样）/ 本周进展（自动记录），每段配一张示意卡片。

## 5. 可访问性与质量门槛
- 所有可点击元素是真实 `<a>` / `<button>` / `<label>`；图标按钮带 `aria-label`
- 文本对比度 ≥ 4.5:1；聚焦样式清晰可见
- 390px 宽无横向滚动；点击区域 ≥ 44px
- 表单基于原生控件（ChoiceChips 基于 radio），提交不依赖客户端状态。说明：页面使用 loading.tsx 流式加载，需要浏览器开启 JavaScript
- 加载中：`loading.tsx` 用卡片骨架；出错：`error.tsx` 保留导航，显示“没加载出来，[重试]”

- **第二批**：全部事项、每周进展、成员、账号、登录、指南、目标
- 每批：单测 + 现有 e2e 适配（只改选择器，不改断言意图）+ 截图（桌面 1440 与手机 390 各一张 / 页面，存 `docs/design/screenshots/`）
